You’ve got the core bridge architecture locked down, but before you start writing code, there are **5 critical edge cases and production requirements** that will trip you up if you don't account for them upfront.

---

### 1. Physical Hardware & Cable Strategy

* **USB OTG & Host Mode:** Android phones must support USB Host mode, and you need a proper USB-C OTG adapter. Standard charging-only cables will fail silently.
* **Device Permission Prompts (Android):** Unlike TCP, physical USB on Android requires explicit user consent via an OS permission dialog (`UsbManager.requestPermission`). You need to handle the asynchronous permission intent before calling `openDevice`.
* **Hot-plugging Events:** Devices will be plugged in and unplugged while the app is open. You need native broadcast receivers (`ACTION_USB_DEVICE_ATTACHED` / `DETACHED` on Android) to auto-reconnect without crashing.

---

### 2. Protocol & HID Report Parsing Specifications

* **Report IDs & Packet Sizing:** Is your device using standard 64-byte HID reports or custom sizes? Ensure your Kotlin/Swift read buffers match the exact endpoint packet size (`ep.maxPacketSize`).
* **Chunking / Framing:** HID data doesn't always arrive as a neat single message. If your hardware sends payload frames split across multiple 64-byte packets, you need a JS/native framing layer (e.g., matching start/end bytes or length headers) to reconstruct complete messages.

---

### 3. Simulator / Emulator Networking Nuances

* **IP Address Logic:** iOS Simulator uses `127.0.0.1`, while Android Emulator requires `10.0.2.2` to target host machine loopback. Ensure your TCP module handles this host distinction conditionally.
* **Network Security Config (Android):** Modern Android blocks unencrypted HTTP/TCP traffic by default. You may need to add a `network_security_config.xml` allowing `10.0.2.2` cleartext traffic for debug builds.

---

### 4. Enterprise & Apple Ecosystem Blockers (iOS CoreHID)

* **iOS 16+ Requirement:** Apple’s `CoreHID` is only available on iOS 16 and above. If you must support older iOS versions, you have to fall back to the External Accessory Framework (EAAccessory) with MFi-certified hardware.
* **Entitlements:** Production CoreHID requires specific USB app entitlements in your Xcode `.entitlements` file and Provisioning Profile.

---

### 5. Developer Experience & Mocking

* **Custom Protocol Payload Definitions:** Document your byte schema (e.g., `[ReportID, CommandByte, ...DataBytes, Checksum]`) before coding UI state so both your React Native state machine and Node.js mock server agree on payload structures.
* **Mock Server Controls:** Expand your `hardware-emulator.js` to accept CLI arguments or a simple UI/CLI menu so you can intentionally inject error states (e.g., checksum failures, unexpected disconnects) to test RN error boundaries.
